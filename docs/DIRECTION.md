# Payo Kapot — 動態版前／後台方向

現有 `index.html` 是**單機原型**（本機儲存）。動態版目標：多人可同時用、資料進伺服器、分前台使用與後台管理。

---

## 1. 兩套入口，一種資料

| | 前台（使用端） | 後台（管理端） |
|---|---|---|
| 給誰 | 級長、工作人員、一般族人 | 頭目／幹部、名冊管理員、系統管理者 |
| 目的 | 查人力、回報狀態、接任務 | 維護名冊、階級、活動、權限 |
| 語氣 | 簡單、手機優先 | 完整、桌機也可 |

建議網址概念：

- 前台：`/app`（或部落自訂網域）
- 後台：`/admin`

---

## 2. 角色權限（建議四層）

1. **訪客／族人**：看公開看板（各階人數）、看自己的資料、更新「可否動員」
2. **級長（kapot 幹部）**：看本級完整名冊、標記本級出勤、發本級通知
3. **部落管理員**：全名冊 CRUD、階級設定、活動／工作編排、匯出
4. **系統管理者**：多部落（若需要）、帳號權限、備份與稽核

先做「部落管理員 + 一般族人」兩層就夠上線；級長權限第二期再加。

---

## 3. 前台：使用者每天會做的事

### A. 人力看板（首頁）
- 本部落各階級人數、可動員人數
- 進行中的活動（例如：豐年祭準備、會所整修）
- 我被分到的工作（若已登入）

### B. 我的資料
- 中文名、族語名、階級、電話、專長
- 一鍵更新動員狀態：可動員／視情況／長期在外
- （選配）上傳大頭照或聯絡偏好

### B2. 個人如何新增自己的資料（建議流程）

前台**不要**做成「任何人都能直接寫進正式名冊」（個資＋假資料風險高）。  
改成下面三種方式，依部落習慣擇一或並用：

#### 方式 A（最推）：管理員發邀請連結
1. 後台：管理員新增一位族人（或只建空白名額）→ 產生**專屬邀請連結／QR Code**  
2. 本人用手機打開連結 → 填寫：華語名、族語名、年段、電話、專長、動員狀態、個資同意勾選  
3. 送出後進入「待確認」；管理員（或級長）按通過 → 出現在前台名冊  
4. 之後本人用同一支手機／帳號登入，只能改**自己的**資料與動員狀態  

適合：豐年祭前大量補登、怕外人亂填。

#### 方式 B：前台「申請加入」＋審核
1. 前台按鈕「我要登錄」→ 填表（同上）  
2. 狀態＝待審核，**正式名冊看不到**  
3. 後台審核通過才進名冊；退回可寫原因（例如年段填錯）  

適合：開放給族人自助，但仍由幹部把關。

#### 方式 C：幹部代填，本人事後認領
1. 級長／管理員先代填華語名＋族語名＋年段  
2. 本人收到簡訊／LINE 連結 → 補電話、專長、同意條款 → 綁定帳號  

適合：耆老、不擅填表者，由年輕人代登。

#### 個人可填／不可填（權限邊界）

| 欄位 | 本人申請／編輯 | 管理員 |
|---|---|---|
| 華語名、族語名 | ✓ | ✓ |
| 電話、專長、動員狀態 | ✓ | ✓ |
| 年段／階級 | 申請時可選；通過後建議**只能管理員改**（或晉級時批次改） | ✓ |
| 歷任頭目／耆老身分 | ✗（申請時不可自封） | ✓ |
| 出現在前台、電話可見範圍 | ✓（同意勾選） | ✓（可覆寫） |

#### 靜態原型現況（現在的 `index.html`）
目前沒有帳號：同一個瀏覽器裡按「新增族人」就能加，等於本機小工具，**還不是**「個人從外網自己登錄」。  
要做真正的個人新增，必須上動態版（邀請連結或申請＋審核）。

### C. 名冊（登入後・三層，手機友善 RWD）
- **分組順序（由年長排起）**：
  1. **歷任頭目**
  2. **部落耆老**
  3. **部落階級**（以**年段**分類，由年長 → 年幼）
- **第 1 層手風琴**：摺起只見**年段／階級名稱**（可附人數）
- **展開**：列出該年段個人（華語名＋族語名）
- **點進個人**：再拉出個人資料面板（手機用底部 sheet）

### D. 活動報到／回報（第二期）
- 活動當天：到場打勾、請假
- 級長看本級出席率

前台不做複雜設定；設定全部放後台。

## 3.1 前台名冊 UI：階級手風琴 → 人名 → 個人資料

前台資訊架構固定為三層：

```
【歷任頭目】
  歷任頭目 ▾
【部落耆老】
  部落耆老 ▾
【部落階級】（年長 → 年幼）
  壯年年段 ▾        ← 手風琴第 1 層
    ├─ 華語名／族語名  ← 第 2 層
    └─ 點進去         ← 第 3 層個人資料
```

### 每一層放什麼

| 層 | UI | 顯示 | 個資強度 |
|---|---|---|---|
| **1. 年段／階級** | 手風琴標題（預設全部摺起），上方有分組標籤 | 名稱、人數 | 低：群體統計 |
| **2. 人名** | 展開後的列表 | **華語名字、族語名稱**；（可選）動員狀態小點 | 中：可辨識個人，無聯絡方式 |
| **3. 個人資料** | 點人名後拉出（手機底部 sheet／桌機右側抽屜） | 依角色與同意顯示專長、狀態、電話等 | 高：才進真正個資 |

### RWD／手機

- 觸控目標至少約 44px；名冊列、手風琴標題易點
- 小螢幕工具列改直向／滿寬按鈕；個人資料用底部 sheet＋安全區
- 搜尋命中時自動展開該年段並高亮該人

### 第 3 層個人資料：依角色顯示

| 欄位 | 本人 | 同級族人 | 級長 | 管理員 |
|---|---|---|---|---|
| 華語名／族語名／階級 | ✓ | ✓ | ✓ | ✓ |
| 專長（可動員相關） | ✓ | ✓（建議） | ✓ | ✓ |
| 動員狀態 | ✓（可自己改） | △ 可只顯示「可／否」 | ✓ | ✓ |
| 電話／Line | ✓ | ✗ 或需本人同意 | ✓（本級） | ✓ |
| 備註／地址／敏感說明 | ✓ | ✗ | △ 最小化 | ✓ |

原則：**電話與敏感備註只出現在第 3 層**，且需登入＋授權。

### 互動建議

1. **手風琴以階級為單位**；預設全部摺起，建議一次只開一個階級。  
2. **人名列可點**：點了不是再嵌一手風琴，而是**拉出個人資料**（手機用底部 sheet，桌機用右側抽屜）。  
3. **個人資料標示「僅授權可見」**。  
4. **電話用按鈕**：`顯示`／`複製`／`撥打`，不要一進詳情就整排明文。  
5. **搜尋**：可搜華語名、族語名；命中時自動展開該階級並高亮該人，仍要再點一次才進第 3 層。  
6. **未登入**：只看各階人數，或連第 2 層人名都不給（後台開關）。  
7. **完整含電話名冊**：只從後台匯出，並留操作紀錄。

### 同意與後台開關（務必有）

- [ ] 允許出現在前台名冊（第 2 層可見華語名＋族語名）  
- [ ] 允許同級看到我的專長  
- [ ] 允許級長看到我的電話  

未勾「出現在前台名冊」者：不出現在第 2 層（第 1 層人數仍可匿名計入）。

### 為什麼這個結構合適

- 摺起單位是**階級**，符合 kapot 看人力的方式。  
- 人名與個資分兩步點，肩窺／誤觸時不會直接看到電話。  
- 「點進去再拉出」比在名單裡再嵌一層手風琴更清楚，也較符合手機操作。

## 4. 後台：管理員要能操作的事

### A. 名冊管理
- 新增／編輯／停用族人（停用優於硬刪，保留歷史）
- 批次匯入 CSV、匯出 Excel／CSV
- 依階級、動員狀態、專長篩選

### B. 階級設定
- 級名、順序（幼→長）、職責說明
- 晉級作業（整批把某級升到下一級）— 豐年祭後最常用
- 級長指派（綁定帳號 ↔ 階級）

### C. 活動與工作（人力真正「被用起來」的地方）
- 建立活動：名稱、日期、地點、需要哪些階級／專長、人數
- 從名冊勾人選人，或依條件自動建議
- 匯出當次工作分配表

### D. 帳號與權限
- 邀請連結／帳號開通
- 角色：族人／級長／管理員
- 操作日誌（誰改了誰的階級、誰匯出了名冊）

### E. 部落基本資料
- 部落名稱、對外簡介
- 是否公開「人數看板」（可只顯示人數、不顯示姓名）

## 5. 核心資料模型（動態版最小集）

```
部落 Tribe
  └─ 年段／階級 Grade
        section: chief | elder | kapot
        顯示序：歷任頭目 → 部落耆老 → 部落階級（年長→年幼）
  └─ 族人 Member（華語名、族語名、gradeId、專長、動員狀態、聯絡）
  └─ 使用者 User（登入帳號，可綁 Member）
  └─ 活動 Event
        └─ 任務 Task（需要的人／專長）
        └─ 指派 Assignment（誰負責、是否確認／到場）
```

之後可加：晉級紀錄、通知、留言、檔案附件。

## 6. 建議技術方向（務實、好維護）

與「之後做動態網頁」對齊，建議一條主線，避免過度拆分：

| 層 | 建議 | 理由 |
|---|---|---|
| 前端 | Next.js（或 Nuxt）+ 手機優先 UI | 前台／後台同一專案，路由分開即可 |
| 後端 API | 同框架 Route Handlers，或獨立 FastAPI | 名冊、權限、匯出都走 API |
| 資料庫 | PostgreSQL（Supabase / Neon 亦可） | 關聯清楚：部落–階級–族人–活動 |
| 登入 | 手機 OTP、Google、或魔術連結 Email | 族人不見得要記密碼 |
| 檔案 | 先不做大檔；CSV 匯出入 DB 即可 | 降低前期複雜度 |
| 部署 | Vercel / Cloudflare + 託管 DB | 靜態原型可繼續當展示，動態版另站 |

原型 `index.html` 可保留為：展示頁、或離線備援匯出格式對照。

## 7. 分期（照這個做不會一次做太大）

### 第一期 — 能共用的名冊（上線最小）
- 登入（管理員 + 族人）
- 後台：階級、族人 CRUD、CSV 匯出
- **個人登錄**：邀請連結或「申請加入」＋管理員審核（見 §B2）
- 前台：看板 + 我的動員狀態
- 單一部落

### 第二期 — 用得上人力
- 活動／工作指派
- 級長看本級
- 通知（LINE Notify / 簡訊／Email 擇一）

### 第三期 — 對齊歲時
- 批次晉級
- 歷年名冊快照（某年豐年祭當下的人力）
- 多部落（若 Payo 要服務多個部落）

---

## 8. 前／後台操作情境（驗收用）

1. **管理員**：後台設年段 → 發邀請連結（或開放申請）  
2. **族人**：手機填自己的華語名／族語名／專長 → 等待審核通過  
3. **族人（已在名冊）**：更新「這個月可否回部落」  
4. **級長**：看本級誰可動員、誰有「架設」專長  
5. **管理員**：建立「會所整修」活動 → 從可動員青年級勾 10 人 → 匯出工作表  
6. **豐年祭後**：後台執行晉級，名冊階級一次更新，看板數字跟著變  

這些步驟都能跑完，動態版就算「可操作、可使用」。

---

## 9. 與現有靜態版的關係

| 現有靜態版 | 動態版 |
|---|---|
| localStorage | 資料庫 |
| 任何人開同一瀏覽器都能改 | 權限分級 |
| 示範級名可改 | 後台正式維護級名 |
| JSON／CSV 本機檔 | 雲端名冊 + 仍可匯出備份 |

建議：動態版 API 的匯出 JSON 盡量相容現有結構（`tribeName` / `grades` / `members`），方便遷移。
